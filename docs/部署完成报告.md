### 关于 `www` 子域

**DNS 里没有「自动补 www」这回事。** `www.6.中国` 是个**三级域名**，和 `6.中国` 是两个
完全不同的名字；不在 `routes` 里显式声明，它就一直 `ENOTFOUND`（打不开）。

已在 `wrangler.toml` 里补上：

```toml
routes = [
  { pattern = "6.xn--fiqs8s",     custom_domain = true },
  { pattern = "www.6.xn--fiqs8s", custom_domain = true }   # ← 新增
]
```

`custom_domain = true` 会让 Cloudflare **自动建 DNS 记录 + 自动签证书**，无需手动操作。

> 证书说明：Cloudflare 免费版 Universal SSL 的 SAN 是
> `DNS:6.xn--fiqs8s, DNS:*.6.xn--fiqs8s` —— **通配符那一项已经覆盖 `www`**，
> 所以不需要额外买证书，绑定后立即可用。

**★ 已把 `www` 归一（因为不归一会真的出问题）**

一开始判断「两个域名功能等价，可以不归一」—— **这个判断是错的**。
后来实测发现：在 `6.中国` 改好设备名，打开 `www.6.中国` 显示的还是默认名。
原因就是 **`localStorage` 按 origin 隔离**，而这两个域名是两个不同 origin，
设备名和配对记忆各存一份。（详见 `docs/6中国上线验证.md` 第四节。）

所以加了归一，实现是 `public/www-redirect.js`：`<head>` 里**同步**加载的同源小脚本，
`www.` 开头就 `location.replace` 到去掉 www 的地址，保留 `path / search / hash`。

> **⚠️ 这段脚本必须是「同源外部 `.js`」，不能写成内联 `<script>`。**
> 线上响应头带 CSP `script-src 'self'`（没有 `'unsafe-inline'`），内联脚本会被
> **静默拦掉** —— 脚本在 DOM 里、控制台不报错、就是不执行。
> 第一版就是内联的，本地正常、线上不生效，查了很久才定位到响应头。
> 顺带把本地服务器也加上了同一套安全头（`server.js` 的 `SECURITY_HEADERS`），
> 避免「本地通过、线上失败」再次发生。

**想做更正统的 301？**（可选，与上面的前端归一无冲突，加了之后前端这段永远不触发）
**Cloudflare 面板 → 6.中国 → 规则 → 重定向规则**：

| 字段 | 值 |
|---|---|
| 请求 URL | `www.6.中国/*`（或「主机名 等于 `www.6.xn--fiqs8s`」） |
| 目标 URL | `https://6.中国/$1`，类型 **301** |

> 为什么没写进 Worker 代码：静态资源由 Assets 优先匹配、**不进 Worker**（这是刻意的计费
> 设计）。要在 Worker 里做域名判断，就得开 `run_worker_first` 把所有静态请求也拉进 Worker，
> 白白增加请求量。重定向规则是 zone 原生能力，零代码、零计费。
> （API 建不了：wrangler 的 OAuth token 没有 zone 级 rulesets/pagerules 权限，
> 返回 `9109` / `10000`，只能面板操作。）

## 三、部署时踩到的坑（记录备查）

1. **`wrangler login` 会超时**：默认只等 120 秒就 `Timed out waiting for authorization code`，且后台跑的时候链接不会显示给你 —— 第一次就是这么失败的。
2. **改用设备码登录**：`wrangler login --device --browser=false`，提示访问 `https://dash.cloudflare.com/oauth2/device/verify` 并输入 8 位码，窗口给到 **5 分钟**，一次成功。
   - 成功标志：`C:\Users\201\.wrangler\config\default.toml` 的 `expiration_time` 被刷新，且带 `refresh_token`（会自动续期，以后不用反复登录）。
3. **`*.workers.dev` 在大陆被 DNS 污染**：本机解析到 `199.59.150.43` / `2001:...:face:b00c` 这类假地址，直连和走代理都是 `status=000`，**不是服务没起来，是域名被墙**。所以只能用自定义域名做验证。
4. **想验证就得有个能通的域名**：借已激活的 `midoai.com` 挂 `flashdrop.midoai.com`，本机直连立刻 200。
5. 首次 deploy 时若 `routes` 里带自定义域名，wrangler 会顺手把 `workers_dev` 关掉，所以显式写了 `workers_dev = true` 保住备用入口。

## 四、TURN 目前是关的（可选开启）

`/api/info` 里 `turn: false` —— 说明还没注入 Cloudflare TURN 凭证。当前状态下的连通策略是：

```
P2P 直连（STUN）  →  打不通则退回 WS 服务器中继
```

**绝大多数场景（同一 Wi-Fi、普通家宽互连）已经够用**；只有「双方都在严格型企业网 / 对称 NAT」时才需要 TURN。

要开启 TURN：

1. Cloudflare 后台 → **Realtime（实时） → TURN** → 创建 TURN Key → 记下 `Key ID` 和 `API Token`；
2. 本机执行（两条，会把密钥加密存进 Worker，**不落代码仓**）：
```bash
cd D:/workbuddy/flashdrop/cloudflare
npx wrangler secret put TURN_KEY_ID
npx wrangler secret put TURN_KEY_SECRET
```
3. 再 `npx wrangler deploy` 一次即生效，`/api/info` 里 `turn` 会变 `true`。

额度闸门已内置：`TURN_MONTHLY_BUDGET_GB = "900"`，Cloudflare 免费额度是 1000 GB/月，超出后 Worker 自动只发 STUN、前端回退 WS 中继 —— **不会偷偷产生费用**。
