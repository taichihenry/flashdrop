## 四、遗留事项与后续补充

### 4.1 双入口问题：`www.6.中国` 打不开 → 已解决

**两轮修复**：第一轮让它能打开；第二轮（真正重要的）把两个域名归一，
否则会出「同一台设备在两个地址下是两个身份」的问题。

---

#### 第一轮：`www.6.中国` 打不开（2026-10-05 19:50，版本 `d6748bac`）

**现象**：`6.中国` 能打开，`www.6.中国` 打不开。

**原因**：DNS 里没有「自动补 www」这回事。`www.6.中国` 是**三级域名**，
和 `6.中国` 是两个完全不同的名字 —— 没有显式绑定就是 `ENOTFOUND`。

**修复**：在 `wrangler.toml` 的 `routes` 里补一条自定义域（`custom_domain = true`
会让 Cloudflare 自动建 DNS 记录 + 自动签证书）：

```toml
routes = [
  { pattern = "6.xn--fiqs8s",     custom_domain = true },
  { pattern = "www.6.xn--fiqs8s", custom_domain = true }
]
```

**验证（全部通过）**

| 检查项 | 结果 |
|---|---|
| 阿里 DoH `www.6.中国` A 记录 | ✅ `104.21.88.44` / `172.67.172.137` |
| `GET https://www.6.中国/` | ✅ **HTTP 200**，0.56s，7985 B |
| TLS 证书 | ✅ 校验通过；SAN = `DNS:6.xn--fiqs8s, DNS:*.6.xn--fiqs8s`（**通配符已覆盖 www**） |
| `/ws`（无 Upgrade 头 / 真实握手） | ✅ `426` / **`101 Switching Protocols`**，与 apex 一致 |

---

#### 第二轮：两个域名 = 两个身份（2026-10-05 20:0x，版本 `73198325`）

**现象**：在 `6.中国` 改好设备名，打开 `www.6.中国` 显示的还是默认名。

**原因**：**`localStorage` 按 origin 隔离，而 `www.6.中国` 和 `6.中国` 是两个不同 origin。**
设备名（`flashdrop.name`）和配对记忆（`flashdrop.pairs`）都只存在各自的本地存储里，
所以互不相认。**不只是名字 —— 配对关系同样会分裂。**

> 这就是第一轮结论里那句「唯一差别是 localStorage 按 origin 隔离」的**实际后果**。
> 当时的判断是"功能上等价、可以不管"，事实证明**这个副作用必须处理**。

**修复思路**：不在两个域名之间同步本地状态（同步不干净、还会漏），直接**归一到一个入口**。
实现是 `public/www-redirect.js`，在 `<head>` 里**同步**加载，`www.` 开头就跳走，
保留 `path / search / hash`（配对链接是 `https://6.中国/#pair=123456` 这种形式，hash 不能丢）。

**★★ 中间踩到一个极难查的坑：CSP 静默吃掉了内联脚本**

第一版我把它写成 `<head>` 里的内联 `<script>`。结果：

- 本地 Node 服务器跑，**完全正常**
- 一部署到线上，**跳转不生效**，但：
  - 脚本明明在 DOM 里（`document.querySelector('head script')` 拿得到，内容也对）
  - 控制台**不报任何错**
  - 在浏览器里手动执行同样的逻辑，结果完全正确
  - 页面本身一切正常，FlashDrop 照常就绪

查响应头才看到根因：

```
content-security-policy: default-src 'self'; script-src 'self'; ...
                                    ↑ 没有 'unsafe-inline'
```

**内联脚本被 CSP 直接拦掉了。** 这套头（还有 `Permissions-Policy` / `Referrer-Policy` /
`X-Content-Type-Options` / `X-Frame-Options`）应该是此前在 Cloudflare 开了
「Security Headers」一键配置留下的，一直没人注意 —— 响应头不像页面内容那样显眼。

**修法：让代码适配 CSP，不削弱 CSP。** 把内联脚本挪成同源外部文件
（`script-src 'self'` 允许同源 `.js`），而不是去加 `'unsafe-inline'`。

**顺带做了一件更重要的事：给本地服务器加上与线上完全一致的安全头**（`server.js` 的
`SECURITY_HEADERS`）。这次的教训就是「本地一个头都没有、线上一整套」，
环境不一致 → 本地测试的结论不可信。加之前先确认页面干净：
无内联事件处理器（`onclick=` 会被 CSP 拦）、无 `eval` / `new Function`（需 `'unsafe-eval'`）—— 都确认过。

> 注意：别把 `Strict-Transport-Security` 加到 http 的本地服务上，会把自己顶到 https 打不开。
> 另外，CDP 注入的脚本（`addScriptToEvaluateOnNewDocument` / `Runtime.evaluate`）
> **不受页面 CSP 限制**，自动化测试的注入手段不受影响。

**验证**

| 检查项 | 本地（带 CSP） | 线上 |
|---|---|---|
| `https://www.6.中国/#pair=123456` → 归一 | ✅ | ✅ **落在 `6.中国`** |
| hash 是否随跳转保留 | ✅ boot 快照 = `#pair=123456` | ✅ 同上 |
| 跳转后页面可用 | ✅ FlashDrop 就绪 | ✅ |
| 直接开主域名不被误跳 | ✅ | ✅ |
| `www.www.www` 逐步收敛不循环 | ✅ 3 跳收敛 | ✅ |

新增测试 `test/www-redirect.js`（用 CDP 的 `addScriptToEvaluateOnNewDocument`
在**文档创建那一刻**打快照取 hash —— 事后读 `location.hash` 必然是空的，
因为 `app.js` 启动时会消费 `#pair=` 并 `history.replaceState` 抹掉它）。

**后续可选**：想换成更正统的 301，去面板 **6.中国 → 规则 → 重定向规则**，
`www.6.中国/*` → `https://6.中国/$1`。加了之后前端这段永远不会被触发，两者不冲突。
API 建不了（wrangler OAuth token 无 zone 级 rulesets/pagerules 权限，返回 `9109`/`10000`）。
**不建议写进 Worker 代码** —— 静态资源不进 Worker 是刻意的计费设计。

### 4.2 繁体 `6.中國` 打不开：注册局已就绪，差 Cloudflare 侧建 zone

**背景**：使用者输入繁体写法 `6.中國` / `www.6.中國` 也应该能访问。

**先厘清一个容易搞错的认知**：

| 写法 | punycode | 说明 |
|---|---|---|
| `6.中国` | `6.xn--fiqs8s` | 简体顶级域，**已上线** |
| `6.中國` | `6.xn--fiqz9s` | 繁体顶级域，**是另一个 TLD** |

> ⚠️ 注意 `.中國` 的 punycode 是 `xn--fiqz9s`，**不是** `xn--kpry57d`（别记错）。
> 用 Node 现算最稳：`new URL('https://6.中國').hostname`。

**现状实测（2026-10-05 20:2x）**

| 环节 | 状态 |
|---|---|
| CNNIC 注册局委派 `6.xn--fiqz9s` | ✅ **已指向 `odin` / `tricia.ns.cloudflare.com`** |
| Cloudflare 账号下的 zone 列表 | ❌ **只有 `6.中国` 和 `midoai.com`，没有 `6.中國`** |
| 实际解析 | ❌ 本机 `ESERVFAIL` / 阿里 DoH `Status=2` |
| 直接问 Cloudflare 权威 NS | ❌ 拒绝应答（zone 不存在） |

**结论**：**`.中国` 和 `.中國` 在 CNNIC 那边是同一份注册数据（简繁等效）** ——
改 `6.中国` 的 NS 时，`6.中國` 跟着一起改了，**注册局那一步已经完成，不用再去 22.cn 操作**。

缺的只有一环：**Cloudflare 账号里没有 `6.中國` 这个 zone**，
所以它的权威服务器拒绝应答，递归解析器只能回 SERVFAIL。

**需要人工做的一步（API 做不了）**：

> API 创建 zone 需要 `com.cloudflare.api.account.zone.create` 权限，
> wrangler 的 OAuth token 没有（返回 `Requires permission ... to create zones`）。

1. Cloudflare 面板 → **添加站点 / Add a site** → 输入 **`6.中國`**（繁体）→ 选 **Free**
2. 它会显示要用的 NS —— **就是 `odin` / `tricia`，和 CNNIC 上现有的完全一致**，
   所以**不需要再去 22.cn 改任何东西**，通常几分钟内自动变 `active`
   （若没自动变，Overview 页点「立即重新检查 / Re-check now」）
3. 建好之后，把 zone id 给过来，剩下两步由代码完成（见下）

**建完 zone 后要做的两步**（已备好，等 zone id）：

1. `wrangler.toml` 的 `routes` 补两条：
   ```toml
   { pattern = "6.xn--fiqz9s",     custom_domain = true },   # 6.中國
   { pattern = "www.6.xn--fiqz9s", custom_domain = true }
   ```
   重新 deploy（`custom_domain = true` 会自动建 DNS 记录 + 签证书）
2. **归一逻辑已经提前部署好了**（版本 `971fa5f0`）：`public/www-redirect.js` 里
   有一份白名单 `FAMILY = ['6.xn--fiqs8s', '6.xn--fiqz9s']`，
   `6.中國` / `www.6.中國` 会自动跳到 `6.中国`。

   为什么繁体也归一到简体：**要让设备名和配对记忆只有一份**。
   浏览器不认「简繁等效」，`6.中國` 和 `6.中国` 依然是两个 origin。
   如果保留繁体作独立入口，今天这个「两个地址两个身份」的问题会原样重演。

   > 白名单而不是「只要不是主域名就跳」，是为了不误伤本地开发（`127.0.0.1`）、
   > `workers.dev` 备用入口和将来任何新绑的域名。测试 `test/www-redirect.js`
   > 的 [4] 段就是钉这个的。

**验证测试**：`node test/www-redirect.js` 的 [3] 段会测繁体归一。
zone 还没建时它会**跳过**（显示 ⏭ 并说明原因），建好后重跑即变 ✅。
