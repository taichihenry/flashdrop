## 四、遗留事项与后续补充

### 4.1 `www.6.中国` 打不开 → ✅ 已于 2026-10-05 19:50 修复

**现象**：`6.中国` 能打开，`www.6.中国` 打不开。

**原因**：DNS 里没有「自动补 www」这回事。`www.6.中国` 是**三级域名**，
和 `6.中国` 是两个完全不同的名字 —— 没有显式绑定就是 `ENOTFOUND`。

**修复**：在 `wrangler.toml` 的 `routes` 里补一条自定义域（`custom_domain = true`
会让 Cloudflare 自动建 DNS 记录 + 自动签证书），重新 deploy（版本 `d6748bac`）：

```toml
routes = [
  { pattern = "6.xn--fiqs8s",     custom_domain = true },
  { pattern = "www.6.xn--fiqs8s", custom_domain = true }
]
```

**验证（全部通过）**

| 检查项 | 结果 |
|---|---|
| 阿里 DoH `www.6.中国` A 记录 | ✅ `104.21.88.44` / `172.67.172.137` |
| `GET https://www.6.中国/` | ✅ **HTTP 200**，0.56s，7985 B |
| TLS 证书 | ✅ 校验通过；SAN = `DNS:6.xn--fiqs8s, DNS:*.6.xn--fiqs8s`（**通配符已覆盖 www**） |
| 内容一致性 | ✅ www 与 apex 首页 md5 **完全相同** |
| `/api/info` | ✅ `{"mode":"public","lanUrls":[],"wsPath":"/ws","wsRelay":true,"turn":false}` |
| 静态资源 `app.js` / `app.css` | ✅ 与本地逐字节一致 |
| `/ws`（无 Upgrade 头） | ✅ `426` —— 说明 Worker 在 www 上正确接管了信令路径 |
| `/ws`（真实握手） | ✅ **`101 Switching Protocols`**，与 apex 表现一致 |

**功能上双入口等价**：同一个 Worker、同一个 Durable Object；房间按出口 IP 划分、
配对码由服务端生成，**跨域名互传完全正常**。唯一差别是 `localStorage` 按 origin 隔离，
「已配对设备记忆」不在两个域名间共享。

**若想统一到主域名**（可选）：面板 **6.中国 → 规则 → 重定向规则**，
`www.6.中国/*` → `https://6.中国/$1`，301。免费且不计 Worker 请求。
API 建不了（wrangler OAuth token 无 zone 级 rulesets/pagerules 权限，返回 `9109`/`10000`）。
**不建议写进 Worker 代码** —— 静态资源不进 Worker 是刻意的计费设计，
在 Worker 里判域名就得开 `run_worker_first`，白白增加请求量。
